# پرامپت تحویل پروژهٔ نور به چت بعدی

تاریخ گزارش: ۲۰ اکتبر ۲۰۲۶. این متن را می‌توان مستقیماً در چت بعدی فرستاد یا فایل آن را پیوست کرد.

---

در پروژهٔ «میزکار پژوهشی نور» کار انتقال طراحی تأییدشدهٔ فیگما به کد موجود را ادامه بده. تاریخچه و وضعیت زیر را مبنای شروع قرار بده؛ قبل از هر تغییر، وضعیت واقعی فایل‌ها و ابزارهای فعلی را بخوان. این پروژه از صفر ساخته نمی‌شود و کار هنوز کامل نشده است.

## ۱. هدف و تصمیم‌های قطعی کاربر

- طراحی تمام صفحات دسکتاپ و موبایل قبلاً در فیگما ممیزی و طی چند مرحله اصلاح شد؛ اکنون در مرحلهٔ انتقال آن به برنامهٔ موجود هستیم.
- آخرین پالت تیرهٔ تأییدشده، با نام «زمرد شب»، مرجع اولیهٔ اجراست. فعلاً همین اسکین جایگزین شود؛ معماری باید توسعهٔ اسکین‌های بیشتر را ممکن کند.
- اجزای مشترک باید یکپارچه باشند: رنگ‌ها از توکن‌های معنایی، ظاهر از کامپوننت‌های قابل استفادهٔ مجدد، و داده‌ها و عملیات از قراردادهای موجود برنامه بیایند.
- از MCP داخلی فیگما حتماً استفاده کن. صرفاً از روی تصویر، توصیف حافظه یا حدس کدنویسی نکن.
- قابلیت‌های فعلی برنامه را حفظ کن. به‌ویژه مطالعهٔ پیوسته از قبل در کد وجود داشت؛ نباید دوباره پیاده‌سازی شود. نمایش صفحه‌محور و پیوسته باید از بالای کتاب و تنظیمات قابل تغییر باشند، در دسکتاپ و موبایل.
- روش بازیابی گذرواژه با کمک مدیر سامانه است؛ کاربر این روش را صریحاً انتخاب کرده است. سامانهٔ ایمیل یا بازنشانی خودکار اختراع نکن.
- مجوز اصلاح ایرادهای کشف‌شده و اجرای بهبودهای مرتبط داده شده است. برای انتخاب‌های عادی اجرایی دوباره تأیید نخواه؛ در صورت نیاز واقعی به اطلاعات یا دسترسی، علت را مشخص کن.

## ۴. استک و معماری موجود

- Next.js App Router، React، TypeScript، Tailwind 4، اجزای shadcn/Radix.
- نسخهٔ نصب‌شدهٔ Next در بررسی قبلی 16.3.8 بود؛ به حافظهٔ نسخه‌های قدیمی Next تکیه نکن. AGENTS.md برنامه می‌گوید قبل از ویرایش مرتبط، راهنمای داخل `node_modules/next/dist/docs/` خوانده شود.
- محصول اصلی یک SPA روی `/` با hash routing است؛ نمونه‌ها:
  `/#/login`، `/#/recovery`، `/#/home`، `/#/library`، `/#/search`، `/#/book/{uid}`، `/#/read/{documentUid}`، `/#/topics`، `/#/research`، `/#/project/{uid}`، `/#/compare`، `/#/settings`، `/#/admin`، `/#/invite?code=…`.
- `src/lib/hash-router.tsx`: مسیرها و مقصد پس از ورود.
- `src/components/app-shell.tsx`: پوسته، احراز هویت و انتخاب view.
- TanStack Query برای دادهٔ سرور و Zustand برای وضعیت برنامه.
- فونت‌ها محلی‌اند؛ Vazirmatn برای رابط و Amiri برای متن عربی، همراه گزینه‌های موجود دیگر.
- backend مستقل Go در `mini-services/noor-api` است. مرورگر `/api/v1` را صدا می‌زند و BFF به API محلی پورت 8080 وصل می‌شود.
- API نویسندهٔ app.sqlite است. منطق جست‌وجو، اندیس، نسخهٔ محتوا و داده‌های پژوهشی را با دادهٔ نمایشی جایگزین نکن.

## ۷. آخرین کار نیمه‌تمام: ورود و بازیابی

این تغییرات در فایل‌ها نوشته شده‌اند، اما **پس از آخرین ویرایش هنوز بررسی نهایی بصری یا کامپایل ثبت نشده است**. نقطهٔ شروع مناسب چت بعدی همین بخش است:

- context فیگما برای `2270:2988` و `2177:5693` با MCP دریافت شد.
- `src/views/login-view.tsx`: استفاده از Field مشترک، placeholderها، نمایش/پنهان‌کردن گذرواژه، loading مشترک، پیام خطای متصل به فرم، اصلاح wrap خطای اتصال و متن راهنما.
- در ورود دومرحله‌ای، تبدیل ارقام فارسی/عربی به ASCII برای کد شش‌رقمی اضافه شد.
- فایل جدید `src/views/recovery-view.tsx`: راهنمای سه‌مرحله‌ای تماس با مدیر، فیلد نام کاربری و بازگشت به ورود. این صفحه صرفاً راهنماست؛ درخواست بازنشانی یا ارسال پیام به مدیر انجام نمی‌دهد.
- `app-shell.tsx`: مسیر عمومی `/#/recovery` اضافه شد و از ذخیره‌شدن آن به‌عنوان مقصد پس از ورود جلوگیری شد. منطق ورود و نشست از store فعلی می‌آید.
- برای توضیح دقیق، خود این سه فایل را بخوان؛ گزارش‌های قدیمی ممکن است هنوز این مرحله را پوشش نداده باشند.

## ۹. مانع اجرای واقعی برنامه

- آخرین بار `/#/search` به صفحهٔ ورود رسید و پیام «سامانه موقتاً در دسترس نیست» نشان داد.
- در بررسی بعدی، listener روی پورت 8080 و process API دیده نشد. این یک مشاهدهٔ تاریخی است؛ اکنون وضعیت را دوباره بررسی کن.
- فرانت در پورت 3000 اجرا شده بود؛ فعال‌بودن آن در چت جدید تضمین نیست. شناسه‌های session و tab چت قبلی را قابل استفاده فرض نکن.
